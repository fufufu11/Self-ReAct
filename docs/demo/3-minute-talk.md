# Self-ReAct 3分钟讲解稿

> 面向面试的口语化讲解稿，按正常语速约 3 分钟讲完（约 900 字）。
> 建议只讲黑体标注的关键句，示例可跳过；时间紧张时删除"真实演示"段落。

## 开场：这是什么（约 20 秒）

**我用 20 天从零实现了一个最小可用的 ReAct 智能体框架，叫 Self-ReAct。**
ReAct 是"推理加行动"：模型不是一次性回答，而是可以调用工具、拿到观察结果、
再继续推理，直到给出最终答案。我没有用 LangChain 这类现成框架，而是自己把
模型接口、工具注册、输出解析、主循环和状态轨迹全部写了一遍——目的是真正理解
智能体应用每一层在做什么。

## 核心循环：怎么实现（约 60 秒）

整个项目就是一条有界的循环，我把它拆成五个职责清晰的模块。

第一，**领域模型**：我用 Pydantic 定义了消息、工具调用、工具结果、观察和
智能体状态。所有跨模块的数据都走同一套契约，类型和必填字段由模型校验。

第二，**模型接口**：我定义了一个只有 `complete(messages) -> Message` 的
`LLM` 协议。Fake LLM 和 DeepSeek 适配器实现同一个接口，所以业务代码完全不
依赖具体供应商，测试也可以全程离线。

第三，**提示词与解析器**：系统提示词只允许两种决策——直接最终回答，或者
请求调用一个工具；解析器把模型的 JSON 输出严格解析成这两种结构，非法输出
会得到稳定的错误，而不是悄悄修补。

第四，**主循环**：`Agent` 是唯一的循环控制者。每一轮检查步数预算、请求模型、
执行工具、把观察写回上下文，直到最终回答或明确的终止原因。

第五，**轨迹**：每一步的输入摘要、决策、观察、错误和耗时都被记录下来，
渲染成人类可读的中文轨迹。

## 工具与错误处理（约 40 秒）

工具层我实现了计算器、受限文件读取和内置知识检索。计算器用 AST 白名单
求值，绝不使用 eval；文件读取被锁在允许的根目录内，越界路径直接拒绝。
所有工具错误统一转换成结构化结果，可恢复的错误会作为观察回写给模型，
让它换一种方式继续——比如先检索失败，再换主题就成功了。

## 测试与质量（约 40 秒）

**自动化测试全部离线、确定性、可复现。** 主循环用 Fake LLM，适配器用注入
客户端，总共 357 个测试，不访问网络、不需要 API Key。端到端示例也做成了
数据加组合：单工具、多工具、失败后恢复三条主线，一条命令就能完整复现。
这也让我能证明文档和演示不是编的，而是真实跑出来的。

## 局限与取舍（约 20 秒）

这是最小 MVP，所以我明确不做持久化、流式、异步和并行调度；知识检索是内置
固定知识库，不是向量数据库。取舍的原则是：每个能力都要能讲清楚、能测试，
而不是把功能堆上去。

## 收尾（约 10 秒）

**这个项目最大的收获，是把智能体应用从"调用框架"变成了"理解每一层"：**
模型决策、工具边界、状态循环和错误恢复，每一层我都能从头讲清楚，也有完整
的测试和历史记录可以证明。谢谢。
